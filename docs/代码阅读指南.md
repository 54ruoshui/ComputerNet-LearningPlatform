# GraphRAG 代码阅读指南

> 面向第一次接触本项目的开发者。按"先看什么、再看什么"组织，覆盖每个文件。

## 一、整体架构：三层分工

```
┌─────────────────────────────────────────────────────┐
│  入口层    run.py → web/graph_rag_web.py (FastAPI)   │  路由、中间件、SSE 流式
├─────────────────────────────────────────────────────┤
│  组件层    src/*.py                                  │  Agent 装配、外部模型调用、存储
│            graphrag_agent.py 是系统心脏              │
├─────────────────────────────────────────────────────┤
│  业务层    src/services/*.py                         │  检索、测验、考试、复习调度、仪表盘
└─────────────────────────────────────────────────────┘
        依赖方向：入口层 → 组件层 → 业务层 → Neo4j / SQLite / 外部 API
```

一句话理解：**外层（src/ 根目录）看"谁在调用谁"（架构），services/ 看"具体怎么做"（逻辑）**。

### 路径 1：理解系统全貌（推荐首次阅读，约需 2-3 小时）

| 4 | `src/graphrag_agent.py` (420 行) | **系统心脏**：ReAct Agent 装配了哪 4 个工具（knowledge_search / graph_statistics / node_search / node_neighbors）、SqliteSaver 会话持久化、流式输出 |
| 5 | `src/services/entity_retriever.py` (363 行) | 检索核心：混合检索（关键词 + 语义向量）→ 合并去重 → 上下文构建的完整流程 |
| 6 | `src/keyword_extractor.py` (50 行) | 检索的前置步骤：Qwen 结构化输出抽取关键词 |
| 7 | `src/embedding_manager.py` (95 行) | 语义检索的向量从哪来（DashScope text-embedding-v3） |

读完这 7 个文件，主链路就通了：

```
用户提问 → FastAPI → Agent(LLM 决策) → knowledge_search 工具
  → KeywordExtractor 抽关键词 → EntityRetriever 混合检索
  → Q&A + Layer 上下文拼装 → LLM 生成答案 → SSE 流式返回
```

## 四、关键横切概念（读代码前先知道）

1. **会话即学生**：`session_id` 贯穿问答（LangGraph SqliteSaver）、刷题、复习、考试，存于浏览器 localStorage（`graphrag_session_id`），是掌握度数据的关联键。
2. **掌握度是曲线驱动的**：刷题答对不会立即标记"已掌握"；由 `record_review()` 依据复习次数、记忆半衰期、回忆质量自动判定（阈值见 `review_scheduler.py` 头部常量）。
3. **两套存储**：Neo4j 存知识本体（图谱、题目），SQLite（`data/memory/mastery.db`）存学习行为（掌握、复习、考试）。Agent 会话内存是另一个 SQLite（SqliteSaver）。
4. **向量索引**：Neo4j `entity_embedding_index`（cosine，1024 维），由 Qwen text-embedding-v3 生成——语义检索的前提，新导入的 Entity 必须跑 embedding 脚本才能被搜到。
5. **SSE 流式**：`/api/query/stream` 返回 `text/event-stream`，前端逐 token 渲染；Agent 的工具调用过程也通过事件流透出。
