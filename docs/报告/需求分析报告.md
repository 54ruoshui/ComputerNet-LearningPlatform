# 需求分析报告

> 项目：基于 AIGC 的动态课程内容生成（大学生创新训练项目）
> 应用场景：计算机网络课程智能学习系统
> 文档版本：2026-09 ｜ 对应申报书四项研究内容

## 一、背景与问题定义

传统计算机网络课程教学存在三大痛点（源自项目申报书"研究目的"）：

1. **内容静态化**：教材与习题固定，无法随学科发展与学生状态动态更新；
2. **更新滞后**：答疑、解析等资源依赖教师人工编写，产能受限；
3. **个性化不足**："一刀切"推送，不感知学生的知识掌握状态与遗忘规律。

本系统以计算机网络学科为场景，用知识图谱 + LLM + 遗忘曲线模型替代"固定教材驱动"，转向"数据与智能驱动"的课程内容生产与分发。

## 二、用户角色

| 角色 | 使用入口 | 核心诉求 |
|---|---|---|
| 学生（主要用户） | 问答页 / 刷题页 / 复习页 / 仪表盘 / 试用评估页 | 精准答疑、按掌握度练习、科学复习、了解自身状态 |
| 研究者（项目成员） | 试用评估页（研究管理视图）+ 评测脚本 | 招募被试开展前测-后测实验，采集学习行为与满意度，产出评估报告 |
| 教师（间接用户） | 仪表盘 / 题库管理 | 掌握班级薄弱点，扩充题库 |

## 三、功能需求

### 3.1 知识问答（对应研究内容 1、2）

| 编号 | 需求 | 实现要点 | 对应 API |
|---|---|---|---|
| Q-1 | 领域问题精准解答 | ReAct Agent 自主调用检索工具，答案基于图谱上下文 | `POST /api/query`、`POST /api/query/stream`（SSE 流式） |
| Q-2 | 检索必须介入领域问题 | 系统提示词约束 + 无工具调用时预检索兜底（`retrieval_fallback` 标记） | 同上 |
| Q-3 | 多轮会话记忆 | SqliteSaver 持久会话，session ID 跨页面共享 | `/api/sessions/*` |
| Q-4 | 答案可解释、可视化 | 答案附检索到的子图，前端 D3 力导向图渲染 | SSE `graph` 事件、`/api/export_graph` |
| Q-5 | 个性化答疑 | 掌握状态 + 遗忘预警注入 Agent 提示词 | `/api/mastery/*` |

### 3.2 习题训练与诊断（对应研究内容 3）

| 编号 | 需求 | 实现要点 | 对应 API |
|---|---|---|---|
| E-1 | 分层分章节刷题 | 按 OSI 层/难度/章节筛选，即时批改与解析 | `GET /api/quiz/questions`、`POST /api/quiz/answer` |
| E-2 | 错题诊断 | 错题自动收录、重做、清空 | `/api/quiz/wrong` 系列 |
| E-3 | AI 动态出题 | LLM 以图谱实体为种子生成 MCQ，预览-编辑-确认入库（`source:'ai'`） | `POST /api/quiz/generate`、`POST /api/quiz/questions` |
| E-4 | 个性化练习推荐 | 基于薄弱点画像（层/难度/章节）加权抽题 | `GET /api/exam/recommendations/{sid}` |
| E-5 | 真题考试与薄弱点分析 | 408 真题在线作答、批改、LLM 薄弱点分析与学习建议 | `/api/exam/*` 系列 |

### 3.3 复习调度与学习闭环（对应研究内容 4 前半）

| 编号 | 需求 | 实现要点 | 对应 API |
|---|---|---|---|
| R-1 | 知识掌握度衰减建模 | R(t)=e^(-ln2·t/S) 半衰期模型，答题事件驱动更新 | `POST /api/quiz/answer`（内部联动） |
| R-2 | 最佳复习时间自动计算 | 目标保留率 R*=0.90 驱动间隔，含间隔效应稳定性更新 | `GET /api/review/due/{sid}` |
| R-3 | 复习推送 | 到期队列 + 7 天负荷预测 | `GET /api/review/state/{sid}`、`/api/review/stats/{sid}` |
| R-4 | 自动掌握判定 | S≥504h 且复习≥3 次且质量≥4 | `GET /api/mastery/{sid}` |
| R-5 | 学习仪表盘 | 掌握/复习/考试/薄弱点聚合 + LLM 学习报告 | `/api/dashboard/*` |

### 3.4 效果评估（对应研究内容 4 后半，本轮新增）

| 编号 | 需求 | 实现要点 | 对应 API |
|---|---|---|---|
| T-1 | 前测-后测实验设计 | 分层平行卷（前/后测互斥、同层同量、seed 可复现） | `POST /api/trial/create` |
| T-2 | 被试管理 | 匿名参试码，绑定学习会话（行为数据自动关联） | `/api/trial/{id}/participants`、`POST /api/trial/join` |
| T-3 | 在线前后测作答 | 题目不含答案下发，整卷提交统一批改，前测完成才解锁后测 | `POST /api/trial/test/start`、`POST /api/trial/test/submit` |
| T-4 | 效果量化分析 | 整体/分层前后测对比、提升率、学习行为、满意度聚合，小样本告警 | `GET /api/trial/{id}/analysis` |
| T-5 | 用户试用评估报告 | LLM 生成评估叙述 + 数据附录，脚本导出为结题交付物 | `POST /api/trial/{id}/report`、`scripts/export_trial_report.py` |
| T-6 | 对比实验 | 系统 vs 通用大模型直答，准确性/覆盖度/满意度三维度 | `scripts/run_eval_comparison.py` → `docs/对比实验报告.md` |

### 3.5 满意度采集（横切）

| 编号 | 需求 | 实现要点 | 对应 API |
|---|---|---|---|
| F-1 | 答案满意度反馈 | 答案气泡 👍/👎，匿名可选留言 | `POST /api/feedback` |
| F-2 | 满意度统计 | 按会话/全局汇总，对比实验与试用评估共用数据源 | `GET /api/feedback/stats` |

## 四、非功能需求

| 类别 | 需求 | 实现 |
|---|---|---|
| 性能 | 接口分级限流，防 LLM 资源滥用 | `web/rate_limiter.py`：查询 10 次/60s、答题 5 次/10s、LLM 出题与报告 5 次/60s、默认 30 次/30s |
| 安全 | 可选 API Key 认证 | `web/middleware.py`（未配置 `API_KEY` 时跳过） |
| 可靠性 | 检索链路失效可检测 | 无 tool_calls 时预检索兜底 + `retrieval_fallback` 标记 + 日志告警 |
| 可维护性 | 配置集中、测试全覆盖 | pydantic-settings 单一配置源；单元/集成测试 212 项（详见《测试报告》） |
| 数据一致性 | Layer 命名兼容 | 图谱「运输层」/MCQ「传输层」双向别名（`LAYER_ALIASES`） |
