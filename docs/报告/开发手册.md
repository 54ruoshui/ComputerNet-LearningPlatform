# 开发手册

> 项目：基于 AIGC 的动态课程内容生成
> 面向：项目成员接手开发 / 部署 / 数据维护
> 服务器部署细节另见《部署指南.md》，逐文件代码导览另见《代码阅读指南.md》

## 一、环境搭建

### 1.1 依赖

- Python 3.11/3.12（conda 环境 `aigc`）
- Neo4j 5.x（含 APOC 可选）
- Graphviz（可选，图谱图片导出用）

```bash
conda activate aigc
pip install -r requirements.txt
```

### 1.2 配置（.env）

必填：

```ini
NEO4J_PASSWORD=...        # Neo4j 密码（URI 默认 bolt://127.0.0.1:7687，用户 neo4j）
ZHIPUAI_API_KEY=...       # 主 LLM（ReAct Agent / 批改 / 各类报告）
```

语义检索与关键词提取还需（二选一即可）：

```ini
QWEN_API_KEY=...          # DashScope Qwen：text-embedding-v3 + 关键词提取
DASHSCOPE_API_KEY=...
```

可选：

```ini
API_KEY=...               # 设置后所有 /api/* 需带 X-API-Key 请求头
ZHIPU_MODEL=glm-4-flash-250414   # 主模型，必须支持 tool_calls（见下"坑"）
WEB_PORT=5001
```

配置由 `src/settings.py`（pydantic-settings）统一管理，必填缺失启动即报错。

## 二、启动与运行

```bash
# Web 应用（默认 http://localhost:5001）
python run.py --mode web [--host 0.0.0.0 --port 5001 --debug]

# CLI 问答 / 冒烟测试（真实调用 LLM）
python run.py --mode cli
python run.py --mode test

# 测试（无需真实 Neo4j/API Key，conftest.py 自动注入测试环境变量）
python -m pytest tests/                     # 全量
python -m pytest tests/unit -v              # 单元
python -m pytest tests/integration          # API 集成
```

页面入口：`/` 问答、`/quiz` 刷题（含考试、AI 出题）、`/review` 复习、`/dashboard` 仪表盘、`/trial` 试用评估。

## 三、数据导入与维护

```bash
# 知识图谱：data/layers/*.json → Neo4j（5 层 OSI + 跨层关系）
python scripts/build_from_json.py

# 实体向量（语义检索前提）：为 Entity 节点生成 Qwen 1024 维 embedding
python scripts/generate_embeddings.py

# 选择题题库导入（--stats 仅看统计；--file 指定 JSON）
python scripts/import_mcq.py

# 408 真题试卷：data/exam_papers/*.json → ExamPaper 节点
#   （或经 UI/API 导入：POST /api/exam/papers/import）
```

数据源文件：

| 目录/文件 | 内容 |
|---|---|
| `data/layers/{1_physical..5_application}.json` + `cross_layer.json` | 知识图谱源 |
| `data/mcq_*.json` | MCQ 题库（多批次，共 414 题） |
| `data/exam_papers/408_*.json` | 408 真题 |
| `data/memory/mastery.db` | SQLite（掌握度/复习/考试/反馈/试用评估） |
| `data/quiz/` | 刷题进度 JSON（已做/错题） |

## 四、评测与评估脚本

```bash
# 对比实验（系统 vs 通用大模型直答，真实 LLM，全量 40-60 分钟）
python scripts/run_eval_comparison.py --mcq-count 1 --qa-count 2 --limit 10   # 冒烟
python scripts/run_eval_comparison.py --report                                # 全量+生成报告
#   产出 eval/comparison_results.json + docs/对比实验报告.md（JSONL 断点续跑）

# 用户试用评估报告导出（前测-后测数据 → 结题交付物）
python scripts/export_trial_report.py --list                # 查看批次
python scripts/export_trial_report.py --trial-id trial_xxxx # 导出 docs/用户试用评估报告.md
```

试用评估操作流程（对应结题"前测-后测试用评估"）：

1. `/trial` 研究管理 → 创建批次（设定每层题量与随机种子）；
2. 添加被试并分发参试码（P####）；
3. 被试在 `/trial` 被试入口输码加入（自动绑定其浏览器学习会话）→ 完成前测；
4. 学习期（≥1-2 周）：被试正常使用问答/刷题/复习，行为自动记录；
5. 被试完成后测；研究者查看"效果分析"，生成/导出评估报告。

## 六、开发约定与已知坑

1. **主模型必须支持 tool_calls**：换模型前先验证会发起工具调用（历史上 glm-4-flash 曾整段静默失效）。验证方法：提问后看 SSE 是否有 `graph` 事件，或日志是否出现 `模型本轮未发起任何工具调用`；兜底机制会置 `retrieval_fallback` 标记；
2. **Layer 命名**：图谱用「运输层」（教材叫法），MCQ 子系统用「传输层」。新写 Cypher 匹配 Layer 时用 `LAYER_ALIASES` 双向兼容（参考 `quiz_service.add_question`）；
3. **`query()` 失败语义**：错误文案会作为 answer 返回（`查询处理失败: ...`），调用方（评测脚本等）必须识别该标记；
4. **新增全局服务**：需在 `web/graph_rag_web.py` 增加懒初始化，并把服务变量纳入 `tests/integration/test_api.py` client fixture 的保存/恢复字典，避免测试间污染；
5. **限流与测试**：集成测试有 autouse fixture 清空限流桶；新增高消耗 LLM 端点时在 `web/rate_limiter.py` 的 `ENDPOINT_LIMITS` 中加条目；
6. **测试环境变量**：`tests/conftest.py` 在 import src 前注入测试值并清 `get_settings()` 的 lru_cache，勿在模块导入期读取环境变量。
