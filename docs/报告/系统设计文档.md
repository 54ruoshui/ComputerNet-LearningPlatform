# 系统设计文档

> 项目：基于 AIGC 的动态课程内容生成
> 文档版本：2026-09 ｜ 代码导览详见《代码阅读指南.md》，本文聚焦架构与设计决策

## 一、总体架构

三层分工，依赖方向单向：**入口层 → 组件层 → 业务层 → 存储/外部 API**。

```
用户（浏览器）
    │
    ▼
FastAPI（web/graph_rag_web.py — 全部路由与服务装配）
  ├── RequestIDMiddleware        请求追踪
  ├── RateLimitMiddleware        按 IP 滑动窗口分级限流（web/rate_limiter.py）
  ├── APIKeyMiddleware           X-API-Key 认证（未配置则跳过）
  └── SSE 流式（POST /api/query/stream：status/graph/token/done 四类事件）
    │
    ▼
GraphRAGAgent（src/graphrag_agent.py — 系统心脏）
  LangGraph ReAct Agent + SqliteSaver 持久会话
  工具：knowledge_search / graph_statistics / node_search / node_neighbors
    │
    ▼
EntityRetriever（src/services/entity_retriever.py — 混合检索）
  关键词提取(Qwen) → 语义检索(向量索引) + 关键词匹配(Cypher) → 合并排序
  → 挂载 QA/层次上下文 → build_context
    │
    ├──────────────────────────────┐
    ▼                              ▼
Neo4j（知识图谱/题库）          SQLite（data/memory/mastery.db）
Layer/Entity/Question/           掌握度/复习状态/考试/反馈/试用评估
MCQuestion/ExamPaper
```

**设计决策**：

1. **服务懒初始化**：全局服务变量 + `init_*` 函数，启动时批量初始化，失败不阻断（对应路由返回 503）；
2. **RAG 优先于微调**：微调实验（Qwen3-8B LoRA）MCQ 准确率与基座持平，主系统采用"通用 LLM + 知识图谱约束"路线，微调产物作为独立实验存档；
3. **算法与存储分离**：`ReviewScheduler` 为纯算法无 DB 依赖，参数集中在文件头部可调；
4. **前后端无框架**：Jinja2 模板 + 原生 JS（每页一个 IIFE），避免构建链路，适配课程部署环境。

## 二、核心子系统设计

### 2.1 ReAct 问答 Agent

- **工具集**（LLM 自主选择）：`knowledge_search`（混合检索问答）、`graph_statistics`、`node_search`、`node_neighbors`；
- **可靠性设计**：主模型必须支持 tool_calls（曾因 glm-4-flash 不发起工具调用导致检索静默失效，详见《已知问题-ReAct工具调用失效.md》）。双保险：① 系统提示词收紧"领域问题必须先检索"；② Agent 兜底——本轮无任何 tool_calls 时自动预检索并重答/补发 graph 事件，响应带 `retrieval_fallback` 标记；
- **个性化**：`MasteryService.build_mastery_context()` 把掌握状态与遗忘预警注入提示词；
- **验证手段**：SSE 是否出现 `graph` 事件。

### 2.2 混合检索（EntityRetriever）

每次查询仅一次关键词提取调用：

1. `KeywordExtractor`：Qwen `with_structured_output` 提取检索关键词；
2. 语义检索：Qwen text-embedding-v3（1024 维）→ Neo4j 向量索引 `entity_embedding_index` → top-K；
3. 关键词匹配：Cypher `CONTAINS` 计分；
4. 合并去重排序 → 补挂 QA（`get_qa_for_entities`）与层次上下文 → `build_context`。

### 2.3 遗忘曲线复习调度（ReviewScheduler）

以记忆半衰期 S（stability）为唯一强度信号：

| 机制 | 公式/规则 | 参数 |
|---|---|---|
| 保留率 | R(t) = e^(-ln2·t/S) | — |
| 复习间隔 | interval = S·log₂(1/R*) | 目标保留率 R* = 0.90 |
| 稳定性更新（间隔效应） | S' = S×(1 + 5.0×(1-R)×q_factor×EF/2.5) | q_factor：{3:0.8, 4:1.0, 5:1.2} |
| 遗忘衰减 | quality<3 时 S' = clamp(S×LAPSE_DECAY, floor, 24h) | — |
| 自动掌握 | S≥504h ∧ 复习≥3 次 ∧ 质量≥4 | MASTERY_* 常量 |

**数据流**：刷题/考试/手动复习 → `MasteryTracker.record_review()`（编排：记录事件 → 调度器更新 → 掌握判定）→ 到期队列（`/review` 页）与掌握上下文（注入 Agent）。

### 2.4 前测-后测试用评估（TrialService，本轮新增）

支撑申报书"前测-后测实验设计评估系统对学习效果的实际提升"：

```
研究者（/trial 研究管理）                     被试（/trial 被试入口）
  创建批次 ──分层抽样──▶ 平行卷                输参试码 ──join──▶ 绑定 session_id
  （pre_ids/post_ids 互斥、                    前测 ──提交──▶ 批改落库
   seed 可复现、存档于批次配置）                系统学习期（问答/刷题/复习，行为自动记录）
  登记被试（P#### 参试码）                      后测（前测提交后解锁）
  效果分析 ◀──── trial_tests/review_events/answer_feedback ────┘
  LLM 评估报告 ──导出──▶ docs/用户试用评估报告.md
```

**关键设计**：

1. **平行卷**：每层从 MCQuestion 池抽 `2×per_layer` 题（`random.Random(seed)`）打散二分，前/后测同层同量且互斥；题目 ID 存档于批次配置，后续题库变动不影响已建批次；
2. **批改不依赖 ExamPaper 节点**：按 `q.id IN $ids` 直查 MCQuestion，保持 Neo4j 干净；
3. **防作弊/防重复**：start 下发的题目剔除 `correct_answer`；`UNIQUE(participant_id, phase)` + 已提交拒绝重交；
4. **行为归因零侵入**：被试绑定 session_id 后，学习行为复用既有 `review_events`（quiz_correct/quiz_wrong/manual）与 `answer_feedback`，无需被试额外操作；
5. **小样本保护**：n<5 时分析结果带 `small_sample_caveat`，LLM 报告提示词强制声明统计显著性限制。

## 三、数据模型

### 3.1 Neo4j

| 节点 | 关键属性 | 说明 |
|---|---|---|
| Layer | name | 5 层 OSI（注意：传输层在图谱中叫「运输层」） |
| Entity | name, entity_type, description, layer, embedding(1024) | Protocol/Device/Concept 子标签 |
| Question / Answer | text | 图谱问答对 |
| MCQuestion | id, text, option_a~d, correct_answer, explanation, difficulty, layer, chapter, source(manual\|ai) | 414 题 |
| ExamPaper | id, title, total_score | 408 真题卷 |

关系：`CONTAINS`（Layer→Entity、ExamPaper→MCQuestion）、`ABOUT`（Question/MCQuestion→Entity/Layer）、`RESPONDS_TO`、`DEPENDS_ON`、`WORKS_WITH`、`APPLY_TO`。

### 3.2 SQLite（MasteryTracker，`data/memory/mastery.db`）

| 表 | 用途 |
|---|---|
| mastery | 学生×实体 掌握标记（曲线自动判定 + 手动覆写） |
| review_state / review_events | 复习调度状态 / 事件流（含评估列：predicted_retention、half_life_after） |
| exam_results / exam_answer_details | 考试成绩与逐题明细 |
| weak_point_profile | 薄弱点画像（layer/difficulty/chapter 三维错误计数） |
| answer_feedback | 答案满意度 👍/👎 |
| **trials / trial_participants / trial_tests**（新增） | 试用批次（含平行卷配置）/ 被试（参试码+会话绑定）/ 前后测作答与批改明细 |

## 四、API 一览

| 分组 | 端点 |
|---|---|
| 问答 | `POST /api/query`、`POST /api/query/stream`(SSE) |
| 会话 | `GET/POST /api/sessions`、`GET /api/sessions/{id}/history`、`DELETE /api/sessions/{id}` |
| 图谱 | `/api/entities`、`/api/graph_stats`、`/api/node_neighbors/{name}`、`/api/search_nodes`、`POST /api/export_graph`、`POST /api/generate_image` |
| 掌握/复习 | `/api/mastery/{sid}`(+batch)、`/api/review/{state\|due\|stats}/{sid}`、`POST /api/review/record` |
| 刷题 | `GET /api/quiz/questions`、`GET /api/quiz/chapters`、`POST /api/quiz/answer`、`GET /api/quiz/stats`、`POST /api/quiz/questions`、`POST /api/quiz/generate`、`/api/quiz/done`、`/api/quiz/wrong` |
| 考试 | `/api/exam/papers`(详情/导入)、`POST /api/exam/submit`、`/api/exam/{analysis\|recommendations\|history}`、`GET /api/exam/result/{id}` |
| 反馈 | `POST /api/feedback`、`GET /api/feedback/stats` |
| 仪表盘 | `GET /api/dashboard/overview/{sid}`、`POST /api/dashboard/report/{sid}` |
| **试用评估（新增）** | `POST /api/trial/create`、`GET /api/trial/list`、`POST/GET /api/trial/{id}/participants`、`POST /api/trial/join`、`POST /api/trial/test/start`、`POST /api/trial/test/submit`、`GET /api/trial/{id}/analysis`、`POST /api/trial/{id}/report` |
| 页面 | `/`(问答)、`/quiz`、`/review`、`/dashboard`、`/trial` |

限流（`ENDPOINT_LIMITS`）：`/api/query` 10/60s、`/api/quiz/answer` 5/10s、`/api/quiz/generate` 与 `/api/trial/report` 5/60s（LLM 耗资源）、其余默认 30/30s。
