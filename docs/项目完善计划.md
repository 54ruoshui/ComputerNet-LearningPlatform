## 一、功能完整性问题（当前系统的实际短板）

### 1. 题库严重不足 + 题型单一

**现状**：`data/mcq_questions.json` 仅30道MCQ。`quiz_service.py:66-122` 的章节结构覆盖43节教材，但实际有题的节约12节。仅支持4选1单选题（`check_answer` 在 `quiz_service.py:143-166` 只对比 `correct_answer` 字段）。缺少判断题、填空题、简答题。

**具体方案**：

- 利用现有LLM + 知识图谱自动生成MCQ
  - 对每节知识点 → 生成题干 + 4个选项 + 解析 + 关联实体（`ABOUT`边）
  - 目标：43节全覆盖，每节≥5题，总量≥200题
- 新增题型：
  - `MCQuestion` 节点增加 `question_type` 属性（`choice`/`true_false`/`fill_blank`/`short_answer`）
  - `QuizService.check_answer` 按题型分支处理：判断题直接对比T/F、填空题关键词匹配
- 新建 `scripts/generate_mcq.py`：批量生成 + 人工审核接口

**涉及文件**：`src/services/quiz_service.py`、`data/mcq_questions.json`、新建 `scripts/generate_mcq.py`

---

### 2. 错题集和已做题用全局JSON文件存储，未按学生隔离

**现状**：`quiz_storage.py:11-14` 定义了两个全局路径 `data/quiz/wrong_answers.json` 和 `data/quiz/done_ids.json`。`get_done_ids()` (L30-32)、`add_wrong()` (L51-59) 等所有函数都不接受 `session_id` 参数。所有学生共享同一个错题集和已做列表。API端点在 `graph_rag_web.py:885-913` 也不接受 `session_id`。但系统其他部分（mastery、review、exam）都是按 `session_id` 隔离的，这里不一致。

**具体方案**：

- 方案A（推荐）：迁移到 mastery.db，新增两张表 `quiz_done(session_id, question_id, done_at)` 和 `quiz_wrong(session_id, question_id, selected_answer, correct_answer, recorded_at)`
- 方案B：文件按 `data/quiz/{session_id}/*.json` 拆分
- 改造 `quiz_storage.py` 所有函数签名增加 `session_id` 参数
- 修改前端 `quiz-app.js` 的 API 调用传入 `session_id`
- 数据迁移脚本处理现有全局数据

**涉及文件**：`src/services/quiz_storage.py`、`web/graph_rag_web.py:885-913`、`static/js/quiz-app.js`

---

### 3. 刷题页未与复习调度/薄弱点联动

**现状**：`quiz_service.py:46-58` 的 `get_questions()` 使用 `ORDER BY rand()` 随机出题。`exam_service.py:349-426` 的 `get_recommendations()` 已实现了基于薄弱点画像的加权推荐（`_build_layer_weights` 等，L428-464），但这个逻辑只在考试页的"针对性推荐"面板使用，刷题Tab完全不调用。

**具体方案**：

- 在 `GET /api/quiz/questions` 增加 `mode` 参数：
  - `random`（默认，保持兼容）
  - `review_priority`：查询 `review_state`，按 retention 从低到高排序关联题目
  - `weak_point`：复用 `ExamService.get_recommendations` 的加权逻辑
  - `adaptive`：根据近期正确率动态调整难度分布
- 前端刷题Tab增加模式切换按钮，默认仍为随机

**涉及文件**：`src/services/quiz_service.py:20-62`、`web/graph_rag_web.py:556-575`、`static/js/quiz-app.js`

### 4. 教材全文RAG检索

**现状**：两本教材的TXT文件已在 `data/docs/`（谢希仁 1.4MB + 自顶向下 1.5MB），但未分块、未向量化、未索引。Agent 只有4个工具，没有教材检索能力。

**具体方案**：

- 新建 `src/services/textbook_service.py`
  - 按章节标题正则分块（chunk_size ~800-1000字，overlap ~150字）
  - Qwen embedding向量化（复用 `EmbeddingManager`）
  - 存入Neo4j `TextbookChunk` 节点（属性：text, book_title, chapter, section, embedding）
  - 创建向量索引 `textbook_embedding_index`
- Agent 新增 `textbook_search` 工具（`graphrag_agent.py:40-101` 的 `make_tools` 中新增）
- 检索结果标注来源（书名+章节），并自动链接相关 Entity 节点

**涉及文件**：新建 `src/services/textbook_service.py`、`scripts/index_textbooks.py`、修改 `src/graphrag_agent.py:40-101`

### 5. 无统一学习仪表盘

**现状**：复习统计在 `/review` 页（`review-app.js:40-63`）、考试统计在考试结果页、掌握状态在主应用侧边栏。没有一个总览页面把所有学习数据聚合展示。

**具体方案**：

- 新建 `GET /api/dashboard/overview/{session_id}` — 一次性聚合：
  - 全局掌握进度（已掌握/学习中/未接触 占比）
  - 各层掌握率
  - 复习统计（同 `/api/review/stats`）
  - 考试正确率趋势
  - 薄弱点 Top 10
  - 最近学习活动时间线
- 前端新建 `/dashboard` 页面：
  - 掌握度热力图（43节 × 颜色深浅）
  - 正确率趋势折线图 + 复习日历热力图
  - 学习报告一键导出（调用LLM生成文字总结 + 图表）

**涉及文件**：新建 `templates/dashboard.html`、`static/js/dashboard-app.js`、修改 `web/graph_rag_web.py`

**现状**：`tests/unit/` 下有 `test_agent.py`、`test_embedding_manager.py`、`test_middleware.py`、`test_settings.py`。但 `review_scheduler.py`（229行，纯函数，极易测试）和 `mastery_tracker.py`（673行，核心业务逻辑）完全没有测试。

**具体方案**：

  - `test_retention_24h` — 半衰期24h时，24h后retention=0.5
  - `test_retention_zero_elapsed` — elapsed=0时retention=1.0
  - `test_half_life_grows_on_good_quality` — quality≥3时half_life增长

### 7. 流式查询每次创建新的数据库连接

**现状**：`graphrag_agent.py:320-328` 的 `_do_stream()` 方法中，每次流式请求都创建新的 `aiosqlite` 连接和 `AsyncSqliteSaver`（L320-323），finally块中关闭（L357）。并发场景下会创建大量短连接。

**具体方案**：

- 在 `__init__` 中持久化一个 `AsyncSqliteSaver` 实例（类似同步版的 `self.checkpointer`）
- `_do_stream` 直接复用，不再每次创建

**涉及文件**：`src/graphrag_agent.py:319-357`

### 8. 中文实体的正则提取有边界匹配问题

**现状**：`entity_service.py:62-68` 的 `extract_entities_from_text` 使用 `re.search(r'(?<![a-zA-Z0-9])' + re.escape(name) + r'(?![a-zA-Z0-9])', text)` 做单词边界匹配。`[a-zA-Z0-9]` 边界对中文无效（中文没有单词边界概念），可能导致中文实体名在文本中被漏匹配或误匹配。

**具体方案**：

- 对纯中文实体名，直接使用 `name in text` 或基于字符边界的匹配
- 对中英混合实体名（如"TCP协议"），保留当前正则但增加中文边界判断

**涉及文件**：`src/services/entity_service.py:61-68`

**涉及文件**：`src/graphrag_agent.py:128-141`、`src/settings.py`、`finetune/`

### 10. 强化学习个性化推荐

**申报书要求**：第六条创新点(2)"引入强化学习算法，结合学生学习行为数据与个体画像，实现课程内容的动态生成、个性化推送与实时迭代"。

**现状**：当前推荐是静态规则（`exam_service.py:428-464` 的加权函数）。无任何 RL 代码。

**具体方案**：

- 第一阶段的合理目标是 Contextual Bandit（LinUCB），因为：
  - 不需要建模状态转移（学生知识状态变化太慢，难以在一个session内学习MDP）
  - LinUCB 在线性reward假设下regret有理论保证
  - 实现简单，可解释
- 状态特征：每个知识点的 retention、review_count、最近 quality、难度、所属层
- 动作：从候选题目池中选择下一道题
- 奖励：答对=+1，答错=-1
- 离线评估：用历史答题记录回放，对比规则推荐 vs LinUCB 的累计奖励

**涉及文件**：新建 `src/services/rl_recommender.py`
